# Design Specification: Auto-Rigging & Skeletal Animation Pipeline (Render3D AI Studio)

## 1. Intent & Problem Statement
Currently, character models generated by Render3D (via Hunyuan3D-2 or the procedural engine) are static T-pose / A-pose meshes. Without skeletal deformation (rigging) and keyframe animation clips, the characters appear rigid and lifeless.

This specification defines an automated, game-ready Auto-Rigging & Animation pipeline based on **Blender Headless + Standalone glTF Skeletal Engine Fallback**. It binds a standard Humanoid Armature to any generated character mesh, applies automatic weight painting, and embeds multiple animation clips (`Walk`, `Idle`, `Run`, `Attack`) directly into an animated `.glb` file that plays in real-time inside the Three.js viewport.

---

## 2. Goals & Non-Goals

### Goals
1. **Motion Preset Library (`assets/animations/`)**:
   - Provide standard humanoid animation clips (`idle`, `walk`, `run`, `attack`) in glTF / FBX / BVH formats.
2. **Blender Headless Script (`scripts/auto_rig_and_animate.py`)**:
   - Automatically normalize character scale (~1.75m height, feet on ground at Y=0, oriented along glTF forward axis).
   - Generate an anatomically aligned Humanoid Armature (Hips, Spine, Chest, Neck, Head, Left/Right Shoulders, Arms, Forearms, Hands, UpLegs, Legs, Feet) matching the mesh bounding box.
   - Bind mesh to armature using `ARMATURE_AUTO` with vertex weight smoothing.
   - Retarget / bake animation tracks into NLA tracks and export a single self-contained animated `.glb`.
3. **Standalone glTF Rigging & Skinning Engine (Zero-Blender Fallback)**:
   - When Blender executable is not installed or available (`blender_available: False`), the system automatically synthesizes a standard humanoid glTF skin with inverse bind matrices and skeletal keyframe tracks (`Walk`, `Idle`, `Run`, `Attack`) so animation works 100% out-of-the-box in all environments.
4. **Backend API (`services/gateway.py`)**:
   - Add endpoint `POST /api/v1/animate-character` (and alias `/api/animate-character`) accepting `task_id` or `glb_path` and `animations: List[str]`.
   - Return URL to animated `.glb` asset with status and clip metadata.
5. **Interactive Three.js Animation Controller (`frontend/index.html`)**:
   - Dedicated animation controls on UI: Action selector (`Đi bộ (Walk)` [Mặc định], `Đứng thở (Idle)`, `Chạy (Run)`, `Tấn công (Attack)`, `Dáng tĩnh (T-Pose)`).
   - Play / Pause button and playback speed slider (`0.5x - 2.0x`).
   - `THREE.AnimationMixer` with smooth `crossFadeTo(action, 0.35, true)` transitions between actions.
   - Auto-plays `Walk` upon initial model load.

### Non-Goals
- Real-time facial motion capture (blendshapes remain neutral during body locomotion).
- Complex physics-based cloth simulation (secondary bone spring dynamics can be added in future iterations).

## 3. System Architecture & Components

```
+---------------------------------------------------------------------------------+
|                                Frontend (Three.js)                              |
|  - THREE.AnimationMixer + THREE.Clock in animate() loop                         |
|  - UI Toolbar: Action Dropdown [Walk (Default), Idle, Run, Attack, T-Pose]      |
|  - Play/Pause Toggle & Speed Multiplier (0.5x - 2.0x)                           |
|  - Smooth crossFadeTo() Transitions                                             |
+---------------------------------------------------------------------------------+
                                      |
                               (HTTP REST API)
                                      v
+---------------------------------------------------------------------------------+
|                           FastAPI Gateway (services/gateway.py)                 |
|  - POST /api/v1/animate-character                                               |
|  - Checks Blender availability:                                                 |
|      * Available   -> calls scripts/auto_rig_and_animate.py                     |
|      * Unavailable -> calls services/dcc/character_rigging_engine.py            |
+---------------------------------------------------------------------------------+
           |                                                      |
           | (Blender available)                                  | (Standalone fallback)
           v                                                      v
+---------------------------------------+      +----------------------------------+
| Blender Headless Pipeline             |      | Standalone Skeletal Engine       |
| (scripts/auto_rig_and_animate.py)     |      | (character_rigging_engine.py)    |
|                                       |      |                                  |
| 1. Auto Bounding Box Alignment        |      | 1. Humanoid glTF Skin Generator  |
| 2. Humanoid Armature Generation       |      | 2. Vertex Weight Assignment      |
| 3. Auto Weight Painting               |      | 3. Synthesized Keyframe Tracks   |
| 4. Animation Retargeting from Library |      |    (Walk, Idle, Run, Attack)     |
| 5. Export NLA Animated GLB            |      | 4. Export Self-Contained GLB     |
+---------------------------------------+      +----------------------------------+
```

---

## 4. Verification & Testing
1. **Script Test**: Execute `scripts/auto_rig_and_animate.py` with test GLB mesh, verifying output GLB contains animations.
2. **Engine Test**: Verify standalone character rigging engine generates valid glTF skin and animation tracks.
3. **Gateway Test**: Call `/api/v1/animate-character` endpoint, verifying HTTP 200 and animated GLB asset creation.
4. **Browser Test**: Verify Three.js AnimationMixer loads the clips and plays `Walk` by default.
